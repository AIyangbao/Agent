# 调试日记：bcrypt 与 passlib 兼容性修复

## 背景

在开发博客后端的用户注册模块时，遇到一个诡异的 bug —— 注册接口始终报 500 错误，日志里写着：

```
ValueError: password cannot be longer than 72 bytes, truncate manually if necessary
```

我明明只输入了 `123456` 作为密码，怎么可能超过 72 字节？

---

## 排查过程

### 1. 检查 security.py

最初怀疑是 `get_hash_password()` 函数没有对密码做截断，于是加了截断逻辑：

```python
def get_hash_password(password: str) -> str:
    password_bytes = password.encode('utf-8')
    if len(password_bytes) > 72:
        password_bytes = password_bytes[:72]
    return pwd_context.hash(password)
```

重启后端，**依然报错**。

### 2. 追踪错误堆栈

仔细看了完整的错误堆栈后发现，错误并**不在我的代码里**，而是在 passlib 库初始化 bcrypt 后端时：

```
passlib/handlers/bcrypt.py, line 380, in detect_wrap_bug
    if verify(secret, bug_hash):
```

`detect_wrap_bug()` 是 passlib 用来检测 bcrypt 库是否存在已知 bug 的内部函数。它在初始化时用一个**测试密码**去调用 bcrypt.hashpw()，而这个测试密码触发了 72 字节限制。

换句话说 —— **我的截断代码根本还没执行到，passlib 自己先崩了**。

### 3. 锁定根因

查了一下版本：

| 组件 | 版本 |
|------|------|
| bcrypt | 5.0.0 |
| passlib | 1.7.4 |

**bcrypt 5.0.0 与 passlib 1.7.4 存在兼容性问题**。从 bcrypt 4.1.0 开始，库加强了对密码长度的校验，而 passlib 1.7.4（最后更新于 2020 年）并没有适配这个变化。

---

## 解决方案

### 方案一：降级 bcrypt（采用）

```bash
pip install bcrypt==4.0.1
```

**注意**：必须确保降级的是后端运行的那个 Python 环境。我用的是 WorkBuddy 托管的 Python 环境，路径是：

```
C:\Users\Administrator\.workbuddy\binaries\python\envs\default\
```

降级后**需要完全杀掉 Python 进程再重启**，`--reload` 不会重载第三方库的变更。

### 方案二：绕过 passlib，直接用 bcrypt

```python
import bcrypt

def get_hash_password(password: str) -> str:
    password_bytes = password.encode('utf-8')
    if len(password_bytes) > 72:
        password_bytes = password_bytes[:72]
    hashed = bcrypt.hashpw(password_bytes, bcrypt.gensalt())
    return hashed.decode('utf-8')

def verify_password(plain_password: str, hash_password: str) -> bool:
    return bcrypt.checkpw(plain_password.encode('utf-8'), hash_password.encode('utf-8'))
```

### 方案三：换用 argon2

```bash
pip install argon2-cffi
```

然后使用 `argon2.PasswordHasher` 替代 bcrypt。argon2 是 2015 年密码哈希竞赛的冠军，目前公认最安全。

## 学到的经验

1. **看错误堆栈要看完整**。表面上是 `get_hash_password` 报错，实际上错误发生在 passlib 库内部初始化阶段。

2. **`--reload` 不够用**。uvicorn 的 `--reload` 只监控代码文件变化，第三方库的升级/降级不会被检测到。环境变更后要手动杀掉进程重启。

3. **passlib 已经停止维护**。passlib 1.7.4 发布于 2020 年，与新版 bcrypt 存在兼容性问题。新项目可以考虑直接用 bcrypt 或迁移到 argon2。

4. **环境管理很重要**。开发时项目可能有多个 Python 环境（venv、系统 Python、工具托管的 Python），安装包时要确认装到了正确的地方。
