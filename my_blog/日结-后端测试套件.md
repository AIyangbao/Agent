# 日结：给博客系统补上自动化测试

> 2026年6月27日 · FastAPI · pytest · 测试驱动

---

## 背景

博客系统的 v1.0 已经跑了两周，注册登录、写文章、标签筛选、软删除全部走通。代码打磨了好几轮，安全性和异常处理也过得去，但一直有个硬伤——**零自动化测试**。每次改点东西，只能手动 curl 或者前端点点点来验证。

今天终于把这个短板补上了。

---

## 测试架构

选型上用了 pytest + pytest-asyncio + httpx 这套组合：

| 组件 | 用途 |
|------|------|
| `pytest-asyncio` | 让测试函数支持 `async def`，因为 FastAPI 全程异步 |
| `httpx.AsyncClient` | 模拟 HTTP 请求，跟真实客户端一样调用接口 |
| `aiosqlite` | 测试环境用 SQLite 内存库替代 MySQL，快且干净 |

关键设计在 `conftest.py`：

1. **SQLite 替代 MySQL**：每个测试会话在内存中创建数据库，建立所有表
2. **外键支持**：SQLite 默认不启用外键约束，需要 `event.listens_for` 手动开启
3. **数据隔离**：每个测试用例前自动删表重建 + 插入 6 个初始标签
4. **双用户 Fixtures**：`auth_client_a` 和 `auth_client_b`，覆盖权限校验场景
5. **依赖注入替换**：`app.dependency_overrides[get_db]` 把真实数据库换成测试库

```python
# conftest 核心思路
@pytest.fixture(autouse=True)
async def setup_db():
    # 重建表 → 插入标签 → yield 跑测试 → teardown
    ...

@pytest.fixture
async def auth_client_a():
    # 注册用户A → 登录拿token → 返回带 Authorization header 的 client
    ...
```

## 踩坑记录

从"全挂了"到"全绿了"，踩了 6 个坑：

### 1. pytest.ini 位置
`asyncio_mode = auto` 必须配置在 `pytest.ini`，放 `tests/` 子目录不会被自动发现，要放在项目根目录 `blog_backend/`。

### 2. login 写成了 register
`test_users.py` 的登录测试里，URL 写成了 `/api/user/register`，测了半天注册接口当登录用。

### 3. Bearer 缺空格
`conftest.py` 构造 Authorization header 时写成了 `Bearer{token}`，JWT 解析器不认，所有鉴权测试 401。

### 4. URL 拼写错误
`test_blogs.py` 有一处 `/apui/blogs/add`，少了个 `a` 多打了个 `u`，404 不是 422。

### 5. 缩进错误
detail 请求被包在 `if` 分支里，某些情况下根本不会执行。

### 6. 字段名不匹配
`add_blog` 原来返回原始 ORM 对象（只有 id、title、content、user_id），测试断言却检查 `tags` 字段。后面改成了 `item => add => get_detail(item.id)` 返回完整的 `BlogResponse`，包含 `tags_name`，但测试里还在找 `tags` 和 `tag_ids`——字段名不匹配，全部返回 `None`。

## 收获

1. **测试基础设施比测试本身更花时间**。conftest 的数据库替换、fixture 设计、环境隔离，这些才是真正的工程量。
2. **SQLite 异步模式的坑比预想的多**。外键要手动开、并发写会锁表、某些 SQL 语法和 MySQL 不完全兼容。
3. **测试能发现 API 设计的不一致性**。比如 `add` 接口返回的结构和 `detail` 不一样——没有测试的时候完全不会注意到。
4. **自动化测试是重构的安全网**。有了这套测试，以后改代码跑一遍就能知道有没有破坏已有功能，不用再手动点点点。
