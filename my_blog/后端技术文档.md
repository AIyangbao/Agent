# 博客后端技术文档（Blog Backend Technical Reference）

> 适用版本：v5（在 v3 基础上新增：图片上传、sitemap、短信验证码登录（实验性·开发中））
> 仓库路径：`F:\Agent\my_blog\blog_backend\`
> 配套文档：部署见 `Docker部署指南.md`；前端架构见前端 README。

---

## 1. 概述

本后端是基于 **FastAPI + SQLAlchemy 2.0 (Async) + MySQL** 的异步全栈 API 服务，负责博客的增删改查、用户认证、音乐列表、RSS 订阅，以及核心亮点功能——**RAG 博客问答系统**与 **Tool-Calling AI Agent**。v5 起新增：图片上传接口、sitemap（SEO），以及处于开发练习阶段的**短信验证码登录**。

### 技术栈

| 领域 | 选型 |
|------|------|
| Web 框架 | FastAPI 0.136.x（ASGI） |
| ORM | SQLAlchemy 2.0（`Mapped` / `mapped_column` 风格，异步 `AsyncSession`） |
| 数据库驱动 | `asyncmy`（异步 MySQL 驱动） |
| 关系型数据库 | MySQL 8.0 |
| 认证 | JWT（PyJWT，HS256，3 天有效期）+ HTTPBearer |
| 密码哈希 | bcrypt（passlib，注意锁 `bcrypt==4.0.1`，5.x 与 passlib 1.7.4 不兼容） |
| LLM / Agent | LangChain + 阿里云百炼（ChatTongyi / TextEmbedding） |
| 向量库 | Chroma 1.5.9（本地持久化 `./chroma_data`） |
| 流式输出 | SSE（`text/event-stream`） |
| 运行时 | uvicorn（容器中由 `docker_start.py` 拉起） |

### 分层架构

```
请求 → Router(routers/) → Service(services/) / curd/
        → Model(models/) + Schema(schemas/) 校验
        → 数据库(AsyncSession, db_conf)
AI 链路：Router(ai.py) → AgentService → LLM 抽象层(llm/) + Tool 注册表(tools/)
RAG 链路：ingest(retrieve/embeddings/store) → Chroma
```

设计要点：**RAG 与 AI 是增强功能，异常必须被吞掉，绝不影响核心发文/读文链路**（见 `services/blog_service.py` 的 `_safe_ingest` / `_safe_remove`）。

## 2. 目录结构与职责

```
blog_backend/
├── main.py                 # FastAPI 入口：挂载路由、CORS、异常处理器
├── docker_start.py         # Docker 启动脚本：等 MySQL → init_db → uvicorn
├── requirements.txt        # 依赖清单（锁定关键版本）
├── config/
│   ├── settings.py         # 配置单例（读取 .env，拼接 ASYNC_DATABASE_URL）
│   ├── base.py             # Base / time_Base 声明基类（含 create_time/update_time）
│   ├── db_conf.py          # 异步引擎、会话工厂、get_db 依赖
│   └── cache_conf.py       # Redis 封装（⚠️ 当前未被业务调用，见第 12 节）
├── models/                 # SQLAlchemy 模型（user, blog, tag, blog_tag, music, chat_history）
├── schemas/                # Pydantic 请求/响应模型
├── curd/                   # 数据访问层（CRUD 原语，不含业务编排）
├── routers/                # API 路由（users, blogs, ai, musics, sms[实验性]）
├── services/               # 业务编排层（blog_service, agent_service, image_service）
├── llm/                    # LLM 抽象层（BaseLLM / QwenLLM / factory）
├── tools/                  # Agent 工具（BaseTool / ToolRegistry / WeatherTool）
├── rag/                    # RAG 引擎（embeddings / store / ingest / retrieve）
└── scripts/
    └── init_db.py          # 建表 + 插入初始标签
├── uploads/                # 运行时：图片上传落盘目录（docker 卷 uploads_data 挂载，非源码）
```

> ⚠️ **包初始化说明**：`config/ curd/ routers/ utils/ models/ schemas/` 目录下**没有 `__init__.py`**，依赖 Python 3 隐式命名空间包（PEP 420）才能被 `from X import Y` 解析。当前可运行，但建议补齐 `__init__.py` 以提升健壮性（否则某些 IDE / 严格打包环境会报导入错误）。

## 3. 数据模型

基类在 `config/base.py`：
- `Base`：`DeclarativeBase` 空基类。
- `time_Base(Base)`：抽象基类，自动附加 `create_time`、`update_time`（`onupdate=func.now()`）。

### 实体关系

```
┌─────────┐       ┌──────────┐       ┌─────────┐
│  user   │ 1   * │  blog    │ *   * │   tag   │
└─────────┘       └────┬─────┘       └─────────┘
   │ id (PK)           │ id (PK)          │ id (PK)
   │ username (uniq)   │ user_id (FK)     │ name (uniq)
   │ password (bcrypt) │ title            │ is_delete
   │ is_delete         │ content          └─────────┘
   └─────────┐         │ is_delete              │
             │         └──────────────┐         │
        ┌────┴────────────────────────┴────┐    │
        │        blog_tag (关联表)          │◄───┘
        │  blog_id (FK) | tag_id (FK)       │
        │  unique(blog_id, tag_id)          │
        └───────────────────────────────────┘

   music(id, title, artist, cover, src)            -- 音乐播放列表
   chat_history(id, user_id, role, content)        -- AI 对话历史
```

### 关键模型字段

| 表 | 字段 | 说明 |
|----|------|------|
| `user` | id, username(uniq), password, is_delete | 密码存 bcrypt 哈希 |
| `blog` | id, title, content(Text), user_id(FK→user.id, CASCADE), is_delete | 软删除；`idx_title`、`idx_user_id` 索引 |
| `tag` | id, name(uniq), create_time, is_delete | 种子数据 6 条：Python/AI/Vue/FastAPI/Docker/其他 |
| `blog_tag` | id, blog_id(FK), tag_id(FK) | 多对多关联，unique(blog_id, tag_id) |
| `music` | id, title, artist, cover(nullable), src | 前端播放器数据源 |
| `chat_history` | id, user_id(index), role(`user`/`assistant`), content(Text) | AI 对话持久化 |

## 4. 配置与环境变量

`config/settings.py` 通过 `pydantic_settings` + `python-dotenv` 读取 `.env`：

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PWD` / `DB_NAME` | MySQL 连接 | 无默认（必填） |
| `JWT_PWD` | JWT 签名密钥（HS256 的 SECRET_KEY） | 无默认（必填） |
| `DASHSCOPE_API_KEY` | 阿里云百炼 API Key（LLM + Embedding 共用） | `""` |
| `QWEN_MODEL` | 对话模型名（如 `qwen-plus` / `deepseek-v4-flash`） | `qwen-plus` |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` | Redis（已接入容器；当前由短信验证码实验性功能使用，RAG/cache 可复用） | redis / 6379 / 0 |
| `DEBUG_MODE` | 调试开关 | `False` |
| `SMS_MOCK` | 短信验证码模式：`true`=不接真实网关、验证码打印后端日志（开发练习用）；`false`=接真实短信网关 | `true` |

连接串拼接：`mysql+asyncmy://{user}:{pwd}@{host}:{port}/{name}?charset=utf8mb4`。

> 部署注意：Docker Compose **只读取项目根目录 `D:\Agent\my_blog\.env`**（与 `docker-compose.yml` 同级），不会读 `blog_backend/.env`。改 `.env` 后需 `docker compose up -d --force-recreate backend` 才能生效。

## 5. 数据库与连接

`config/db_conf.py`：
- `async_engine = create_async_engine(ASYNC_DATABASE_URL, pool_size=10, max_overflow=20)`
- `AsyncSessionLocal = async_sessionmaker(bind=async_engine, expire_on_commit=False)`
- `get_db()` 依赖：`yield session` → 成功 `commit()`，异常 `rollback()`，最终 `close()`。所有路由通过 `Depends(get_db)` 拿到会话。

`scripts/init_db.py`：`Base.metadata.create_all(checkfirst=True)` 建表 + `INSERT IGNORE` 6 条种子标签。
> ⚠️ **已知坑**：`init_db.py` 只 `from config.base import Base`，**未 import 具体模型类**，因此 `Base.metadata.sorted_tables` 在独立运行时可能为空 → `create_all` 建不出表。生产环境曾因此漏建 `chat_history`，已手动补 SQL 建表。修复方式：在 `init_db.py` 顶部 import 全部 model 模块。

## 6. API 接口文档

统一响应封装（`utils/response.py`）：
- 成功：`{"code":200, "message":"...", "data":...}`
- 失败：`{"code":<http_code>, "message":"...", "data":null}`（HTTP 状态码同步返回）

### 6.1 用户 / 认证 `/api/user`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/register` | 否 | 用户名查重 → bcrypt 哈希 → 建用户 → 直接签发 JWT |
| POST | `/login` | 否 | 校验用户名+密码 → 签发 JWT（3 天有效期） |
| PUT | `/password` | — | **占位接口，当前未实现**（直接 `return`） |

请求体（`schemas/users.py` `UserRequest`）：`{username, password}`。

### 6.2 博客 `/api/blogs`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/list_blogs` | 否 | 列表；支持 `tagId`、`keyword`（LIKE 标题+正文）、`page`、`pageSize`(≤100)；返回 `{list, total}` |
| GET | `/detail?id=` | 否 | 详情；附带 `tags_name` 列表；不存在返回 404 |
| POST | `/add` | **是** | 发文；`tag_ids` 可选；走 `create_blog_with_rag`（写库+增量入向量库） |
| DELETE | `/delete?id=` | **是** | 软删除；校验文章归属（非作者 403）；走 `delete_blog_with_rag` |
| PUT | `/update?id=` | **是** | 改文；校验归属；走 `update_blog_with_rag`（upsert 向量） |
| GET | `/rss?limit=` | 否 | 公开 RSS 2.0（`application/rss+xml`），链接形如 `https://blog.fireflyai.site/posts/{id}` |
| POST | `/upload_image` | **是** | ⭐ v5 新增：图片上传（`multipart/form-data`，字段 `file`）；仅限 `image/*`、≤10MB；返回 `data.url`（相对路径 `/api/blogs/uploads/{日期}/{uuid}{ext}`）；后端按日期分目录落盘，由 `main.py` 的 `StaticFiles` 挂载在 `/api/blogs/uploads` 提供访问（依赖 `python-multipart`） |
| GET | `/sitemap.xml` | 否 | ⭐ v5 新增：返回全站文章 URL 的 XML sitemap（`application/xml`），供搜索引擎收录；线上由 nginx 反代 `/sitemap.xml` → 本接口 |

### 6.3 音乐 `/api/music`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/list` | 否 | 返回全部音乐（按 id desc），`MusicResponse` 列表 |

### 6.4 AI 问答 `/api/ai`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/chat` | **是** | **SSE 流式**问答。先持久化 user 消息 → RAG 检索（失败降级为纯聊天）→ 流式返回 token → 流末推送 `citations` |
| GET | `/history?limit=` | **是** | 取当前用户对话历史（asc，含 `role`/`content`），默认 50 条 |
| DELETE | `/history` | **是** | 清空当前用户对话历史 |

**`POST /api/ai/chat` 响应流格式**（`text/event-stream`，每行一个 SSE `data:`）：
```
data: {"reply":"你"}          # 逐 token
data: {"reply":"好，"}
...
data: {"citations":[{"title":"...","link":"...","distance":0.42}]}   # 流末，仅当有引用
data: {"error":"..."}         # 异常分支
```
请求体（`schemas/ai.py` `ChatRequest`）：`{message, history: list[dict]}`。

### 6.5 短信验证码登录（实验性 · 开发中）⚠️

> 本节为开发练习内容，**尚未随 v5 正式上线**。当前采用 **mock 模式**（不接真实短信网关，验证码打印到后端日志），用于跑通全链路。上线前需补充：用户表 `phone` 字段、真实短信网关（阿里云/腾讯云）、发送限流与防爆破。

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/sms/send` | 否 | 发送验证码：生成 6 位码 → `SETEX sms:code:{phone} 300 <code>`（5 分钟过期）→ mock 打印；请求体 `{phone}` |
| POST | `/sms/login` | 否 | 验证码登录：校验 `sms:code:{phone}` → 按手机号查/建用户 → **复用 `create_access_token({"sub": user.id})` 发 token**（与密码登录通用）；请求体 `{phone, code}` |

**练习要点**：
- 验证码存 Redis，`SETEX` 设 300s TTL，校验后 `DELETE` 防重放。
- 安全三件套：① TTL 过期；② 发送 60s 冷却（`sms:cooldown:{phone}`）；③ 登录失败计数防爆破。
- 业务下沉思路同 `services/image_service.py`：校验/落盘等逻辑放 `services/`，路由只做编排。

## 7. 认证机制

- **签发**：注册/登录成功后 `create_access_token({"sub": str(user_id)})`，HS256，默认 3 天过期。
- **校验**：`utils/auth.py` 的 `get_current_user` 依赖 `HTTPBearer`，从 `Authorization: Bearer <token>` 取 token → `verify_token` 解码 → 查库确认用户存在。
- **密码**：`utils/security.py`，`passlib[CryptContext(schemes=["bcrypt"])]`，>72 字节截断后再哈希。

## 8. RAG 博客问答系统（核心亮点）

RAG 模块分四层，目录 `rag/`：

| 层 | 文件 | 职责 |
|----|------|------|
| L1 向量化 | `embeddings.py` | `qwen3.7-text-embedding`，**1024 维，输出已 L2 归一化**；批量 `_BATCH_SIZE=8` 防限流；`embed_query` 复用同模型保证同语义空间 |
| L2 向量存储 | `store.py` | Chroma `PersistentClient(path="./chroma_data")`，集合 `blog_chunks`，`hnsw:space=cosine`；`add_chunks` 用 `upsert`（同 ID 覆盖），`query(top_k)` |
| L3 入库流水线 | `ingest.py` | `split_text`（块 500 字 / 重叠 50 字）；`ingest_all`（全量，过滤正文 <50 字噪声文）；`ingest_one`（增量，upsert）；`remove_one`（按 `post_id` 删 chunk） |
| L4 检索 | `retrieve.py` | 问题向量化 → `query(top_k=3)` → **`STM_THRESHOLD=0.85` 余弦距离过滤不相关块** → 拼 `context` + `citations` |

**发文 / 改文 / 删文的 RAG 数据同步**（`services/blog_service.py`）：
```
POST /add
  → create_blog_with_rag
      → curd.add_blog（写 MySQL）
      → _safe_ingest（try/except 吞异常）→ ingest_one(id, title, content)

DELETE /delete
  → delete_blog_with_rag
      → curd.delete_blog（软删 MySQL）
      → _safe_remove → remove_one(id)（清向量库对应 chunk）
```
> RAG 失败只打印日志，不影响业务返回——这是刻意设计的容错边界。

**首次部署必须初始化向量库**：
```bash
docker compose run --rm backend python -c "import asyncio; from rag.ingest import ingest_all; asyncio.run(ingest_all())"
```

## 9. AI Agent 运行时

`services/agent_service.py` 实现 **ReAct 循环**（Think → Act → Observe → Answer）：

- `AgentService` 无状态，每次请求新建；`MAX_ITERATIONS=5` 防死循环。
- `chat(message, history)`：非流式，返回完整字符串。
- `chat_stream(message, history, rag_context)`：**流式**，逐 token `yield`；若 LLM 决定调工具则先 `tool.execute` 再继续循环。
- `_build_messages`：把 `rag_context`（如有）注入 **System Prompt** 末尾，指示模型优先基于检索内容回答并注明来源；再拼接历史（`user`→HumanMessage，`assistant/ai`→AIMessage）与当前问题。

**LLM 抽象层**（`llm/`）：
- `BaseLLM`（ABC）：`invoke(messages, tools)` / `stream(messages, tools)`。
- `QwenLLM`：封装 `langchain_community.ChatTongyi`，`temperature=0.7`，支持 `bind_tools` 函数调用。
- `factory.get_llm()`：读 `settings` 创建实例，缺 `DASHSCOPE_API_KEY` 抛错。

**Tool 体系**（`tools/`）：
- `BaseTool` / `ToolDefinition`：统一工具接口（name/description/JSON-Schema 参数 + `execute`）。
- `ToolRegistry`：单例注册表，启动时 `register(WeatherTool())`。
- `WeatherTool`：调用外部微服务 `dify_work_api`（`http://localhost:8081/weather`，Bearer `itcast`），查城市天气；带超时/连接失败友好降级。**需该微服务在线才能命中工具分支**。

## 10. Docker 启动流程

`docker_start.py`（容器内入口）：
1. `wait_for_mysql()`：用 asyncmy 轮询 MySQL，最多 30 次（2s 间隔）。
2. `subprocess.run(["python","scripts/init_db.py"])`：建表 + 种子标签。
3. `os.execvp("uvicorn", ["uvicorn","main:app","--host","0.0.0.0","--port","8000"])`。
